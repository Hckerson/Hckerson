# Project Instructions

This is **hckerson.com**, a personal portfolio on **Next.js 16 (App Router), React 19, TypeScript and Tailwind CSS v4**, built to the conventions of the `next-setup` starter. Content drives every page: projects, skills, work history, education, certifications and pricing live in one data file, and the routes derive from it.

## Non-negotiable rules

1. **No hardcoding.** Site identity, contact links, flags, durations, enums, and copy that appears twice live in `lib/constant.ts` or feature-scoped `lib/<feature>/constants.ts`. Every internal path comes from `routes` (`routes.project(id)` for a project), every absolute URL is built from `siteConfig.url` (`NEXT_PUBLIC_SITE_URL`), every mail link from `contactHref` / `contactHrefFor`. Content and sample data live in `lib/data/`, never inline in a page.
2. **Match the existing architecture.** Do not invent patterns, and do not invent locations — when you are unsure where something goes, re-read this file. State the reason before deviating.
3. **Single source of truth.** Name a recurring decision once as a semantic token and reference it everywhere. Define once, change in one place.
4. **Minimize LOC.** Ship the shortest solution that stays maintainable.
5. **No `console.log`, `console.error`, or debug statements** in committed code. The error boundaries (`app/error.tsx`, `app/global-error.tsx`) are the one exception: they report the error they caught.
6. **Never delete a feature because it is not built.** Unbuilt, stubbed, scaffolded, hidden and placeholder are states of work in progress — not evidence the thing was abandoned. This binds content, types, constants, routes and components alike: an export nothing imports yet, a route kept out of the nav, a flag set to off. `/pricing` still resolves while `showPricing` is `false`, on purpose. Removal needs an explicit instruction naming the feature; if you believe something is genuinely dead, say so and wait.

## Required patterns

| Need               | Use                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Styling            | Token-first: colour, surface and text tokens live in `app/globals.css` — `:root` holds the dark default, `.light` overrides it — and reach Tailwind through `@theme inline` (`bg-surface-primary`, `text-text-muted`, `text-accent-cyan`, `border-border`). Type scale through the `xs-text` … `xxlarge-text` classes and section padding through `md-pad` / `large-pad` / `xlarge-pad` and `md-pady` / `large-pady` / `xlarge-pady`, never per-breakpoint `text-[Npx]` or padding chains. Style with Tailwind utilities on house tokens, responsive prefixes included (`xs` is 480px); promote a pattern to a named class only when it repeats. No raw colours in JSX. |
| Class names        | Merge through `cn()` from `lib/utils.ts` (clsx + tailwind-merge) so caller overrides win.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Fonts and icons    | The display face is the `font-clash` utility (Clash Display via `next/font/local` in `lib/fonts.ts`), never an import of the font object. Icons come from `lucide-react`; brand marks (GitHub, X) live in `components/ui/brand-icons.tsx`, because lucide is removing its brand icons.                                                                                                                                                                                                                                                                                                                                                                                  |
| Theme              | Dark is the default. An inline script in `app/layout.tsx` puts `light` or `dark` on `<html>` before paint; `hooks/useTheme.tsx` treats that class as the source of truth. Light mode is the `light:` variant or the `.light` token overrides, never a second component.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Motion             | Durations and easings are the `--motion-*` tokens in `app/globals.css`, mirrored in `lib/constant.ts` — see `docs/MOTION.md`. Animation in React uses `motion` (`motion/react`), installed with its first consumer; never `framer-motion`. Respect `prefers-reduced-motion`.                                                                                                                                                                                                                                                                                                                                                                                            |
| Component patterns | Reuse `components/ui/` (primitives and site chrome) and `components/ui/cards/` before writing JSX. Homepage sections live in `components/sections/`. A pattern used twice is promoted out of the page that birthed it.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Domain types       | Content shapes live in `lib/interface.ts`, shared unions in `lib/types.ts`. Components import types; they never declare shared ones. A field drawn from a fixed set uses a union, not `string`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Content            | `lib/data/mapped-data.ts`: one array per content kind, annotated with its interface and exported from the single block at the foot of the file. Adding a project there is enough — `/projects`, the homepage section and the prerendered `/projects/[id]` pages derive from it. A project `id` is its URL — never renumber one. Personal work in `workExperience` is `kind: "personal-project"`, never `"employment"`. `resumeData` assembles the resume from these same arrays plus the resume-only lists beside it; the PDF declares no content of its own.                                                                                                           |
| Page composition   | A route `page.tsx` composes sections and holds page-level state — nothing else. Mock/seed data goes to `lib/data/`, JSX blocks to `components/`. No inline data array, no inline sub-component.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| State management   | Content is static: Server Components import it from `lib/data/`. `useState` / `useReducer` / URL params for local state. `useSyncExternalStore` for browser state (`useTheme`, `useMediaQuery`), with `localStorage` for persistence. A global store or a data-fetching library requires a stated reason.                                                                                                                                                                                                                                                                                                                                                               |
| SEO                | Site metadata, viewport and the JSON-LD person schema live in `app/layout.tsx`; route metadata is `export const metadata` or `generateMetadata`, typed with `Metadata` from `next`. The rest are file conventions: `sitemap.ts`, `robots.ts`, `manifest.ts`, `opengraph-image.tsx`, `apple-icon.tsx`. Sitemap entries and `generateStaticParams` for `/projects/[id]` derive from `projects`, never a hard-coded id list.                                                                                                                                                                                                                                               |
| Resume             | `/resume.pdf` (`app/resume.pdf/route.ts`) renders `components/resume/resume-pdf.tsx` with `resumeData` through `@react-pdf/renderer`, once at build time. The library never reaches the browser: no client component imports anything under `components/resume/`, and the download is a plain link to `routes.resume`. The PDF's print palette lives in `pdf-styles.ts`.                                                                                                                                                                                                                                                                                                |
| Validation         | Zod schemas in `lib/validations/` for any input the site accepts. Types derive with `z.infer`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| IDs                | Content `id`s are hand-assigned (see Content). Runtime IDs: `nanoid`. Never `uuid` or `Date.now()`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

`components.json` is the shadcn config; its aliases point at these same homes.

Skills written for `next-setup` (such as `cinematic-web`) name that starter's paths. Here they map to: `styles/tokens.css` and `styles/globals.css` → `app/globals.css`; `lib/hooks/` → `hooks/`; `lib/constants.ts` → `lib/constant.ts`. A folder this table lacks, such as `components/wrappers/`, is added on first use and then listed here.

## File rules

- **One component per file.** Kebab-case filename matching the default export (`project-card.tsx` → `ProjectCard`). The one exemption is a primitive family in `components/ui/` consumed as one unit: `accordion.tsx` carries its parts, `brand-icons.tsx` its marks. Everywhere else, prefixing a helper with the file's name does not make it a part — it gets its own file.
- **Hooks** are named for the hook, in camelCase (`useTheme.tsx` → `useTheme`), with a default export.
- **Absolute imports via `@/`.** Never deep-relative (`../../../lib/...`).
- **Any file over ~150 lines gets split**, `page.tsx` included. Data moves to `lib/data/`, JSX to `components/`. Content files in `lib/data/` and the token sheet `app/globals.css` are exempt.

## Before you commit or push

There are no git hooks — no Husky, no lint-staged. Nothing runs on commit or push.

- **Gate** — `pnpm lint`, then `pnpm typecheck`, then `pnpm build`. Run those by hand when you want the gate.
- **Format** — `pnpm format` (Prettier with `prettier-plugin-tailwindcss`, which sorts class names; 4-space indent) is a full-repo sweep; `pnpm format:check` reports without writing.
- **Deploy** — `NEXT_PUBLIC_SITE_URL` must be set to the deployed origin, or canonical URLs, OpenGraph images and `sitemap.xml` point at `localhost`.

The rules above are not restated here. They bind every edit, not the gate.
